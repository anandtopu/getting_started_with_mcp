# Feature map

Coverage contract updated October 30, 2026. **Modules 00–21, bonuses B1–B4 and all five capstones are delivered.** A row closes only when its runnable example, use case, captured exchange, exercises/solutions and tests are delivered. Direct links below identify the delivered sources.

The map covers the core protocol, official extension inventory, selected SDK facilities, and the requested application curriculum. It does not imply that every SDK implementation detail is a protocol feature. Framework compatibility and verified primary API references are recorded in [frameworks](../frameworks/README.md) and Module 15.

## Path rules

All paths are relative to the repository root. Delivered table links below point directly to implementations. Tier 1–5 captures group related operations into scenario files listed in each module's `wire/manifest.json`; example basenames need not equal capture filenames. The example column names a basename:
- Python example: `modules/<module>/python/examples/<basename>.py`.
- For modules 02–05 and 10, TypeScript counterpart: `modules/<module>/typescript/examples/<basename>.ts`.
- Other TypeScript counterparts: `modules/<module>/typescript/examples/` (see each track README for its topic names).
- Use case: `modules/<module>/python/use_case/main.py` (the named scenario in the table), plus the corresponding TypeScript `use_case/main.ts`.
- Every module supplies three numbered practice/apply/stretch exercise files, matching solutions, and `python/tests/test_module.py`; TypeScript mirrors these where required.
- Capture: `modules/<module>/wire/<basename>.jsonl`; its manifest records the exact generating command and dependency versions. Exercises and tests reference those files rather than handwritten transcripts.
