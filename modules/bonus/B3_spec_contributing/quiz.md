# Read the spec: quiz

1. What is normative prose?

<details><summary>Answer</summary>

The specification text defining requirements such as MUST and SHOULD; a tutorial is not an alternative contract.
</details>

2. Does valid JSON prove protocol conformance?

<details><summary>Answer</summary>

No. Capability, sequencing, ownership, transport and security requirements need separate checks.
</details>

3. Why record both SDK version and protocol revision?

<details><summary>Answer</summary>

They change independently, and an SDK may implement more than one revision.
</details>

4. Does an accepted SEP prove released SDK support?

<details><summary>Answer</summary>

No. Verify the released specification, package version and an actual exchange.
</details>

5. What belongs in a useful contribution?

<details><summary>Answer</summary>

A minimal synthetic reproduction, exact versions, a specific expected behavior, observed output and a regression test.
</details>

6. Who should receive a vulnerability report?

<details><summary>Answer</summary>

Follow the project security policy and private reporting channel, not a public issue containing secrets.
</details>
